# Start New Project

Этот файл нужен как техническое задание для создания нового монорепозитория по образцу текущего проекта.

## Главное правило

`repo-root` создавать не нужно.

Корень репозитория уже существует.
Задача состоит только в том, чтобы создать и настроить всё, что должно лежать внутри уже существующего корня репозитория.

## Целевая структура репозитория

```text
repo-root/
  desktop/
    assets/
    css/
    img/
    package.json
    main.js
    preload.js
    renderer.js
    index.html

  web/
    README.md

  mobile/
    README.md

  server/
    README.md

  scripts/
    run-target.js

  docs/
    start.md
    npm.md
    dev/
      README.md
    help/
      README.md

  package.json
  package-lock.json
  .gitignore
  README.md
```

## Что должно быть реализовано

Нужно не просто создать папки, а сразу подготовить рабочую структуру монорепозитория.

Минимальные требования:

- `desktop/` должен быть рабочим desktop-приложением.
- `web/`, `mobile/`, `server/` пока могут быть пустыми направлениями, но папки должны существовать и внутри должен лежать хотя бы `README.md`.
- `scripts/run-target.js` должен маршрутизировать команды из корня монорепозитория по target.
- корневой `package.json` должен быть настроен как точка входа для запуска из корня.
- документация в `docs/` должна быть создана сразу.

## Стандарт запуска, который обязательно нужно реализовать

Из корня монорепозитория должны работать такие команды:

```bash
npm install
npm start
npm start -- desktop
npm start -- --target desktop
npm run dev -- desktop
npm run check -- desktop
npm start -- web
npm start -- mobile
npm start -- server
```

Правила поведения:

- `npm start` должен запускать target по умолчанию.
- target по умолчанию: `desktop`.
- `npm start -- desktop` должен запускать тот же desktop-клиент явно.
- `npm start -- --target desktop` должен поддерживаться как именованная форма выбора target.
- `npm run dev -- desktop` должен быть явной dev-командой для desktop.
- `npm run check -- desktop` должен запускать проверку desktop.
- `npm start -- web`, `npm start -- mobile`, `npm start -- server` пока могут не запускать реальные приложения, но должны завершаться понятным сообщением, что соответствующая часть репозитория ещё не настроена.

Если в проекте сразу нужна упаковка desktop-приложения, дополнительно должны работать:

```bash
npm run pack
npm run dist
```

## Что должно быть в корневом `package.json`

В корне должен быть настроен npm workspace и корневые команды маршрутизации.

По смыслу там должны быть:

- `workspaces` c `desktop`
- `start`
- `dev`
- `check`
- при необходимости `pack`, `dist`, `prod:smoke`

Корневой `package.json` не должен напрямую запускать Electron.
Он должен передавать команду в `scripts/run-target.js`.

## Что должен делать `scripts/run-target.js`

Этот файл является маршрутизатором запуска.

Он должен:

- принимать имя команды: `start`, `dev`, `check`, при необходимости `pack`, `dist`, `prod:smoke`
- уметь принимать target как позиционный параметр
- уметь принимать target как `--target desktop`
- использовать `desktop` как target по умолчанию для `npm start`
- запускать workspace `desktop`, если выбран `desktop`
- проверять наличие `package.json` у `web`, `mobile`, `server`
- если у target ещё нет собственного `package.json`, завершаться с понятным сообщением, что target зарезервирован, но ещё не настроен

## Что должно быть в `desktop/package.json`

Внутри `desktop/` должен быть отдельный `package.json` desktop-приложения.

Минимально он должен содержать:

- `start`
- `dev`
- `check`

Рекомендуемый смысл:

- `start` ведёт в `dev`
- `dev` запускает Electron из исходников
- `check` проверяет основные JS-файлы desktop-приложения

Если нужна упаковка:

- `pack`
- `dist`
- при необходимости `prod:smoke`

## Что должно быть в `docs/start.md`

`docs/start.md` нужен как короткая стартовая точка входа в уже созданный проект.

Это не общий стандарт на все проекты, а именно стартовый файл для следующего открытия репозитория.

В нём должно быть коротко и ясно зафиксировано:

- какая структура уже создана
- что desktop перенесён в `desktop/`
- что `web/`, `mobile/`, `server/` пока являются заготовками
- что запуск идёт из корня монорепозитория
- что `npm start` запускает `desktop` по умолчанию
- что `npm start -- desktop` тоже поддерживается
- что `npm run dev -- desktop` и `npm run check -- desktop` являются рабочими командами
- что `npm start -- web` пока выдаёт понятную заглушку

Практический смысл `docs/start.md`:

- это файл, который можно дать при следующем открытии проекта
- он быстро вводит в контекст без необходимости читать весь репозиторий

## Что должно быть в `docs/npm.md`

`docs/npm.md` должен быть отдельным документом со стандартом npm workflow для проекта.

Этот файл нужно использовать как основной стандарт запуска и сборки.

В нём обязательно должны быть зафиксированы:

- что проект запускается через npm-скрипты
- что `npm start` является основной повседневной командой
- что `npm run dev` является явной технической dev-командой
- что desktop-проект запускается из исходников, а не из готового `.exe`
- что `pack` и `dist` отделены от ежедневной разработки
- что target `desktop` является текущим рабочим target по умолчанию
- что поддерживаются явные формы `npm start -- desktop` и `npm start -- --target desktop`

Если этот файл уже выдан отдельно, его нужно просто положить в `docs/npm.md` нового проекта и реализовать проект в соответствии с ним.

## Что положить в `docs/dev/README.md`

Короткое описание технической документации разработчика.

Пример смысла:

- в `docs/dev/` лежат технические заметки по реализации
- сюда складываются документы по Electron, иконкам, сборке, IPC, структуре файлов и другим внутренним решениям

## Что положить в `docs/help/README.md`

Короткое описание пользовательской и обзорной справки.

Пример смысла:

- в `docs/help/` лежат общие документы по проекту
- сюда складываются обзорные материалы, пояснения по системе тем, интерфейсам и другим частям продукта

## Что не нужно создавать заранее

Не нужно вручную создавать:

- `node_modules/`
- `dist/`

Они появляются позже:

- `node_modules/` после `npm install`
- `dist/` после `npm run pack` или `npm run dist`

## Что нужно передать в другой проект

Если этот шаблон переносится в другой проект, достаточно передать:

- этот файл: `docs/start new project.md`
- файл стандарта npm: `docs/npm.md`

Этого достаточно, чтобы в другом проекте создать:

- структуру монорепозитория
- desktop-target
- корневой npm-запуск
- поддержку `npm start`, `npm start -- desktop`, `npm start -- --target desktop`
- заготовки для `web`, `mobile`, `server`
- базовую документацию в `docs/`

## Короткий вывод

Да, по этому файлу и по `docs/npm.md` можно в другом проекте полностью создать такую структуру и настроить запуск через npm из корня монорепозитория, включая `desktop` как target по умолчанию и явный запуск с параметрами.
